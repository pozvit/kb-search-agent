# KB Search Agent

Сервис отвечает на вопросы о проектах, пропозалах и продуктах консалтинговой компании по её базе знаний. Пропозал — коммерческое предложение компании клиенту. Каждый ответ сопровождается ссылками на карточки реестров и фрагменты документов. Если надёжно ответить нельзя (данных в базе нет, ответ не подтверждается источниками, сломан компонент), сервис не делает вид, что ответ есть, а передаёт вопрос ответственному.

Итоговая работа курса «ИИ-инженер», траектория «ИИ-агенты». Исходная версия — агент из модуля по ИИ-агентам (тег `baseline-2026-10-02`), итоговая — тег `final-2026-11-20`.

**Пользователи** — аналитики и консультанты, готовящие пропозалы. Им нужны референсы по отрасли, услуге и периоду, команда, которую можно указать в пропозале, и формулировки из прошлых пропозалов. Сейчас такой подбор занимает 1–2 часа на один пропозал. Подробнее — [паспорт проекта](docs/project_passport.md).

Сравнение на одинаковых данных и сценариях: контрольный набор из 16 сценариев (17 шагов), модель qwen2.5:7b-instruct на CPU. Протокол — [docs/results_final.md](docs/results_final.md).

## Быстрый старт: Docker

Нужен Docker Desktop с WSL 2 (на Windows) и около 8 ГБ памяти для Docker: модель qwen2.5 занимает в памяти около 6 ГБ.

```bash
git clone https://github.com/pozvit/kb-search-agent.git
cd kb-search-agent
docker compose up -d
python tools/smoke_api.py
```

Первый запуск занимает 20–40 минут: скачивается модель (около 4,7 ГБ), собирается образ, при первом старте контейнера собирается индекс. Следующие запуски — меньше минуты. `tools/smoke_api.py` использует только стандартную библиотеку Python и ждёт готовности сервиса до 10 минут. Ожидаемый итог — `5 из 5 проверок пройдено`; результат проверки в свежем клоне — [reports/deploy_check.txt](reports/deploy_check.txt).

Что поднимает `docker-compose.yaml`:
- `ollama` — сервер модели;
- `ollama-pull` — однократно скачивает модель и завершается;
- `api` — сервис на `http://127.0.0.1:8000`. Порт открыт только на этом компьютере: у сервиса нет авторизации.

```bash
docker compose logs -f api       # журнал: одна строка JSON на событие, без текста вопросов
docker compose down              # остановить; модель, индекс и очередь обращений остаются в томах
```

Интерактивная документация API — `http://127.0.0.1:8000/docs`.

## Примеры запросов

```bash
curl -s http://127.0.0.1:8000/health

curl -s -X POST http://127.0.0.1:8000/ask -H "Content-Type: application/json" \
     -d '{"question": "Какие проекты были в медицине?"}'
```

В PowerShell кириллицу в теле запроса нужно передавать байтами UTF-8:

```powershell
$q = @{ question = "Какие три цифровых решения входят в цифровое ядро AIMS?" } | ConvertTo-Json
Invoke-RestMethod http://127.0.0.1:8000/ask -Method Post -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($q)) | ConvertTo-Json -Depth 4
```

| Вопрос | Что происходит | Время |
|---|---|---|
| Какие проекты были в медицине? | подагент «Реестры»: полный список карточек по отрасли, без вызова модели | < 1 с |
| Кто выполнял эти проекты? (с тем же `session_id`) | люди по карточкам прошлого ответа | < 1 с |
| Кто делал больше всего проектов в операционной эффективности? | рейтинг людей по числу проектов | < 1 с |
| Проекты Белозёровой за последние 3 года | карточки сотрудника за период; фамилия в любом падеже | < 1 с |
| Какие три цифровых решения входят в цифровое ядро AIMS? | подагент «Документы»: поиск в документе AIMS, ответ модели со ссылками, проверка привязки | 30–60 с |
| А что там с внедрением? (с тем же `session_id`) | уточнение: поиск остаётся в документе прошлого ответа | 30–60 с |
| Сколько стоит лицензия SIPS? | данных о стоимости в базе нет — обращение к ответственному (E2) | ~40 с |
| Соедините меня с ответственным за реестр проектов | обращение к ответственному (E4), без вызова модели | < 1 с |
| Какая погода будет завтра? | вопрос вне базы знаний — вежливый отказ без поиска | ~5 с |

Реестры в профиле `public` синтетические: 40 вымышленных карточек и 10 вымышленных сотрудников (`tools/make_synthetic_registry.py`). Ответ `/ask`:

```json
{
  "request_id": "c1f0b7d2-…", "session_id": "3f2c9a1e-…",
  "status": "answered", "route": "registry", "route_path": ["registry"],
  "answer": "В реестрах найдено (отрасль: Pharma & HC): 5. …",
  "sources": [{"type": "card", "id": "project:P02", "title": "Стратегия развития сети клиник", "year": 2022, "industry": ["Pharma & HC"]}],
  "escalation": null, "warnings": [], "grounding": null, "error_code": null,
  "duration_ms": 14, "llm_calls": 0
}
```

Статусы: `answered`, `not_found`, `escalated`, `smalltalk`, `rejected`, `degraded`, `error`. Некорректный запрос — HTTP 422, внутренняя ошибка — 500 без подробностей, сервис не готов — 503; формат ошибки — `{"error": {"code", "message", "request_id"}}`. Полное описание API — [docs/architecture.md](docs/architecture.md), раздел 3.

## Как устроен агент

```
вопрос
  → guardrails: пусто, длина, секреты, явный top_k
  → маршрутизатор: правила по порядку, классификатор для неоднозначных вопросов
      ├─ «Реестры»    выборка из каталога карточек, ответ без модели
      ├─ «Документы»  модель выбирает поиск → поиск → ответ модели → проверка привязки
      │                 не подкреплено → одна перегенерация → эскалация E1
      ├─ эскалация    обращение к ответственному (E1–E4)
      └─ smalltalk    приветствие или вопрос вне базы
  → ответ, источники, trace; память сессии
```

Что изменилось по сравнению с baseline:

1. **Маршрутизатор и подагенты** вместо одного агента. Вопросы к реестрам (перечисления, люди, рейтинги) отвечаются выборкой из каталога без модели; неоднозначные вопросы классифицирует модель коротким вызовом без инструментов.
2. **Подагент «Документы» без фильтров реестра в схеме.** В baseline модель ставила к вопросам о продуктах фильтры годов и отраслей синтетического реестра и отрезала все документы, отвечая «нет информации». Теперь в схеме только `query` и `top_k`, а фильтр по документу продукта ставит код. Промпт сократился с 2 464 до 665 токенов.
3. **Проверка привязки к источникам.** Каждое утверждение сверяется с процитированным фрагментом: общие слова и все числа. Не подкреплено — одна перегенерация, затем эскалация. В baseline ответ без ссылок получал `answered` с пометкой.
4. **Эскалация к человеку**: инструмент `escalate_to_human`, очередь обращений с номерами, правила E1–E4, ответственные — роли из конфигурации.
5. **Сервис**: HTTP API (FastAPI), сессии, структурированный журнал без персональных данных, Docker.

Компоненты, правила маршрутизатора, алгоритм проверки привязки, журнал и обработка ошибок — [docs/architecture.md](docs/architecture.md). Все развилки — [scenario.md](scenario.md).

## Установка без Docker

Нужны Python 3.10+ и [Ollama](https://ollama.com).

```bash
python -m venv .venv
source .venv/bin/activate              # Windows: .venv\Scripts\activate
pip install -r requirements.txt
ollama pull qwen2.5:7b-instruct        # около 4,7 ГБ
python src/build_index.py --profile public
```

Сборка индекса: 5 PDF и синтетический реестр, 89 чанков. При первом запуске скачивается модель эмбеддингов `intfloat/multilingual-e5-small` (471 МБ).

```bash
python src/serve.py                    # HTTP API на http://127.0.0.1:8000
python src/agent_cli.py                # диалог в консоли: /reset, /memory, /trace, /exit
python src/agent_cli.py -q "Какие проекты были в медицине?" --show-trace
```

Без Ollama и без модели эмбеддингов (проверка оркестрации, а не качества ответов): `pip install PyYAML PyPDF2 pytest`, `python src/build_index.py --profile public --no-embed`, затем `--llm mock --retriever lexical`.

## Конфигурация

Параметры — в `config/agent.yaml`: модель и её параметры, лимиты, маршрутизатор, пороги проверки привязки, ответственные за эскалацию, параметры сервиса, профили данных. Переменные окружения перекрывают YAML; полный список с пояснениями — `.env.example`. Ключей API сервису не нужно: модель локальная. Основные переменные:

```
AGENT_PROFILE=public                  # public — синтетика и обезличенные PDF; full — рабочая база
AGENT_LLM_BASE_URL=http://localhost:11434
AGENT_LLM_MODEL=qwen2.5:7b-instruct
AGENT_LLM_BACKEND=ollama              # mock — без модели
AGENT_RETRIEVER=qdrant                # lexical — BM25 без модели эмбеддингов
RAG_EMBEDDINGS_ALLOW_DOWNLOAD=1       # 0 — модель эмбеддингов только из локального кэша
ESCALATION_QUEUE_PATH=data/escalations/escalations.jsonl
LOG_LEVEL=INFO
LOG_FORMAT=json                       # text — для чтения глазами
```

Тест `tests/test_configuration.py` проверяет, что в `.env.example` описана каждая переменная, которую читает код, а у ключей и токенов в шаблоне нет значений.

## Данные и безопасность

| Профиль | Что внутри | Где |
|---|---|---|
| `public` | 5 обезличенных PDF о продуктах; синтетический реестр (40 карточек, 10 вымышленных сотрудников) | в репозитории и в Docker-образе |
| `full` | рабочая база: реестры проектов и пропозалов (1 074 карточки), тексты 486 пропозалов в PDF | только на компьютере владельца; в репозиторий и образ не попадает |

- Реестры, тексты пропозалов, индексы, очередь обращений, trace и `.env` — в `.gitignore` и `.dockerignore`; это проверяют тесты.
- Журнал строится по белому списку полей: текста вопросов и ответов, имён файлов, фамилий и сообщений исключений в нём нет.
- Запрос с ключом API, токеном или паролем отклоняется до модели и не попадает в память, журнал и очередь.
- Ответственные за эскалацию — роли из конфигурации, а не люди.
- `tools/hygiene.py --build-denylist` строит на компьютере владельца список отпечатков фамилий сотрудников из полной базы. Проверка находит эти фамилии в любом падеже, а самих фамилий в списке нет. Перед сдачей эта проверка нашла две фамилии в старых примерах, и история репозитория очищена.

## Ограничения

- **Время ответа по документам** — 30–75 с на CPU, медиана 41,6 с при цели 36 с (у baseline 42,5 с). Время уходит на генерацию ответа; рычаги — лимит длины ответа и меньше фрагментов в контексте — не проверялись.
- **Проверка привязки лексическая.** Она ловит утверждения без ссылки, ссылки «не туда» и чужие числа, но не смысловую ошибку при верных словах — например, утверждение из процитированного фрагмента о другом случае.
- **Сервис однопользовательский:** без авторизации, запросы выполняются по одному. Локальный Qdrant открывается одним процессом, поэтому агент в сервисе один, а память у каждой сессии своя.
- **Контрольный набор невелик** (16 сценариев) и в части реестров синтетический. На полной базе итоговая версия проверялась вручную, количественного замера на ней нет: её данные нельзя публиковать.
- **Маршрутизатор распознаёт отрасли, услуги и периоды по словам и шаблонам.** Необычную формулировку разбирает классификатор, и он может ошибиться.
- **В одном перечислении — до 50 карточек;** для больших выборок агент просит уточнить условия.
- **Порог score для отсечения нерелевантных фрагментов не используется:** у e5 на этой базе промах и попадание имеют почти одинаковый score (0,8498 и 0,8575).
- **Эскалация не рассылает уведомлений:** обращения копятся в локальной очереди.
