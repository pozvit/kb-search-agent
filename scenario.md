# Сценарий работы агента

Итоговая версия (тег `final-2026-11-20`). Сценарий агента модуля — в теге `baseline-2026-10-02`. Компоненты и обмен данными — [docs/architecture.md](docs/architecture.md).

**Назначение одним предложением:** агент отвечает на вопросы о проектах, пропозалах (коммерческих предложениях) и продуктах компании по базе знаний, а если надёжно ответить нельзя — передаёт вопрос ответственному.

## Входные и выходные данные

| | Описание |
|---|---|
| **Вход** | Вопрос на русском языке, 1–1 000 символов; в API — необязательный `session_id` для уточняющих вопросов. В вопросе можно задать `top_k=N` (от 1 до 10) |
| **Выход** | `status`, текст ответа, маршрут и цепочка маршрутов, источники (карточки реестров или фрагменты документов), обращение к ответственному при эскалации, итог проверки привязки, предупреждения, trace |
| **Статусы** | `answered`, `not_found`, `escalated`, `smalltalk`, `rejected`, `degraded`, `error` |

## Основной сценарий: вопрос по документам

```
Пользователь: «Какие три цифровых решения входят в цифровое ядро AIMS?»
        ↓
1. GUARDRAILS  — строка, 1–1000 символов, секретов нет → допущен
        ↓
2. ROUTER      — в вопросе название продукта AIMS → подагент «Документы»
        ↓
3. FILTER      — код находит документ AIMS по метаданным и ограничивает поиск им
        ↓
4. PLAN        — модель получает промпт подагента и схему: search_knowledge_base(query, top_k), list_documents
                 → search_knowledge_base(query="цифровое ядро AIMS", top_k=4)
        ↓
5. ACT         — аргументы проверяются, лишние отбрасываются; e5 → Qdrant → 4 фрагмента документа AIMS
        ↓
6. ANSWER      — модель отвечает по фрагментам со ссылками [Фрагмент N]
        ↓
7. GROUNDING   — каждое утверждение сверяется с процитированным фрагментом: слова и числа
                 подкреплено → answered; нет → одна перегенерация; снова нет → эскалация E1
        ↓
8. RESPOND     — answered, ответ, источники; память сессии +2 сообщения
```

Стоимость: 2 вызова модели (план и ответ) и 1 вызов инструмента. Вопросы к реестрам — перечисления, люди, рейтинги — обходятся без модели: подагент «Реестры» отвечает выборкой из каталога карточек за доли секунды.

## Точки принятия решений

| Точка | Условие | Переход |
|---|---|---|
| guardrails | пусто, не строка, длиннее 1 000 символов, секрет | `rejected`, модель и инструменты не вызываются |
| guardrails | в вопросе `top_k=N` | значение фиксируется; некорректное — `error / invalid_argument`, молча не исправляется |
| маршрутизатор | приветствие | `smalltalk` без вызова модели |
| маршрутизатор | просьба связаться с человеком | эскалация E4 |
| маршрутизатор | перечисление, рейтинг, люди по прошлому ответу, проекты сотрудника | подагент «Реестры» |
| маршрутизатор | название продукта, вопрос о содержании, уточнение прошлого ответа | подагент «Документы» |
| маршрутизатор | остальное | классификатор: реестры, документы или вне предметной области (вежливый отказ) |
| «Документы» | модель передала аргумент вне схемы | аргумент отбрасывается, предупреждение |
| «Документы» | по документу продукта ничего не найдено | поиск по всей базе, предупреждение |
| «Документы» | модель не вызвала поиск | принудительный поиск (`forced_search`) |
| «Документы» | модель недоступна | `degraded`: найденные фрагменты без генерации |
| «Документы» | индекс недоступен, или недоступны и модель, и поиск | эскалация E3 |
| «Документы» | ответа нет, вопрос о данных, которых в базе не бывает (стоимость, контакты) | эскалация E2 |
| «Документы» | ответа нет в остальных случаях | `not_found` |
| проверка привязки | не подкреплено после перегенерации | эскалация E1 |
| лимит итераций | 3 круга «модель → инструменты» исчерпаны | финальный вызов модели без инструментов |

## Сценарии проверки

**Контрольный набор** — `config/control_scenarios.yaml`, 16 сценариев, 17 шагов. Ожидаемые результаты заданы идентификаторами документов и условиями выборки по каталогу. Прогон — `tools/run_control.py`; результаты baseline и итоговой версии — [docs/results_final.md](docs/results_final.md).

**12 исходных сценариев модуля** — `config/agent_scenarios.yaml`:

| ID | Запрос | Итоговая версия |
|---|---|---|
| `main_aims` | Какие три цифровых решения входят в цифровое ядро AIMS? | `answered`, паспорт, пульс, биржа |
| `main_ergo` | Сколько сегментов рынка моделируется в ERGO? | `answered`, 5 сегментов |
| `alternative_not_found` | Стоимость лицензии SIPS для 500 сотрудников | `escalated` (E2), ни одной суммы — в baseline `not_found` |
| `alternative_list_documents` | Какие документы есть в базе знаний? | `answered` через `list_documents` |
| `alternative_smalltalk` | Привет! | `smalltalk`, 0 вызовов модели и инструментов |
| `error_top_k_range` | …AIMS, top_k=0 | `error / invalid_argument`, «от 1 до 10» |
| `error_top_k_type` | Что такое SIPS? top_k=пять | `error / invalid_argument`, «целым числом» |
| `guardrail_secret` | …ключ sk-proj-… | `rejected`, ключа нет в trace |
| `guardrail_empty` | пустая строка | `rejected / empty_query` |
| `tool_failure_index` | вопрос по AIMS, индекса нет | `escalated` (E3), подсказка `build_index` — в baseline `error` |
| `tool_failure_llm` | вопрос по AIMS, Ollama недоступна | `degraded`, найденные фрагменты без генерации |
| `recovery_followup` | 1) Что такое SIPS? 2) А какой объём электрификации путей там был? | во 2-м шаге поиск в документе SIPS, ответ 135 км |

У `alternative_not_found` и `tool_failure_index` ожидания изменены по правилам E2 и E3 ([docs/requirements.md](docs/requirements.md), Q5).
